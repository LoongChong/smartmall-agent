## 切真模型的失败点（已踩）
- DeepSeek 本身**不提供 embedding API**。`.env.example` 默认的 `text-embedding-ada-002` + DeepSeek base URL 是不可用组合（404/400）。
- 解决方案：embedding 改走硅基流动（`https://api.siliconflow.cn/v1`，`BAAI/bge-m3`，dim=1024）。`deepseek_compatible` 这个 provider 名其实就是 OpenAI 兼容协议的占位，名字误导但能接任何兼容服务。
- 已修改 `.env`：
  - `SMA_LLM_PROVIDER` `mock` → `deepseek`（保留用户原 DeepSeek key）
  - `SMA_EMBEDDING_PROVIDER` `hash` → `deepseek_compatible`
  - `SMA_EMBEDDING_BASE_URL` `https://api.deepseek.com/v1` → `https://api.siliconflow.cn/v1`
  - `SMA_EMBEDDING_MODEL` `text-embedding-ada-002` → `BAAI/bge-m3`
  - `SMA_EMBEDDING_DIM` `256` → `1024`
  - `SMA_EMBEDDING_API_KEY` 留占位 `<在这里贴你的硅基流动 API key>`，**用户必须自己填**。
- 陷阱：Pydantic 把任何非空字符串当成"已设置"——占位字符串也会被当成真 key 发请求，结果就是 401。填完之后 `python -c "from sma.config import get_settings; s=get_settings(); print(s.embedding_api_key_value[:6])"` 应该以 `sk-` 开头。
